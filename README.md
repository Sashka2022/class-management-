# ביחד — אבטיפוס לניהול שיעור

אבטיפוס React בעברית וב־RTL, עם נתוני הדגמה בלבד. כולל מסך מחנכת, שלט המותאם לנייד ומסך הקרנה נפרד.

## הפעלה מקומית

נדרש Node.js 22 ומעלה.

```sh
npm ci
npm run dev
```

מסך הכניסה בנתיב `/`. בוחרים כניסת מורה וכיתה, או כניסת אדמין. הסיסמה בשני המסלולים היא `1111`. אפשר להגיע ישירות לבחירת כניסת אדמין ב־`/?view=admin`. לאחר כניסת מורה, פותחים את ההקרנה והשלט מהכפתורים באפליקציה; הקישורים כוללים את מזהה הכיתה כדי לשמור על הפרדה בין הכיתות. לבדיקת הסנכרון פתחו את המסכים בלשוניות באותו דפדפן ובאותו מקור (host ופורט).

```sh
npm run build
npm run preview
```

אם תיקיית מטמון npm הרגילה אינה ניתנת לכתיבה בסביבת הענן, אפשר להשתמש ב־`npm ci --cache /tmp/beyachad-npm-cache`.

## מה אפשר לנסות

- כניסה למורים לכל כיתה וכניסה נפרדת לאדמין, עם הסיסמה המשותפת `1111`.
- מסך אדמין עם סיכום כיתות, תלמידים, נוכחות אחרונה, שיעורים שהסתיימו ולבבות מצטברים; אפשר להוסיף כיתות חדשות.
- ארבעה שקפים מובנים, מעבר ישיר והצגת פעילות עם חזרה לשקף האחרון.
- שלבי שיעור, עריכת הנחיות, הוספת שלב וטיימר עם השהיה והוספת דקה.
- נוכחות, הגעה באיחור, הוספה בהדבקת רשימה, עריכה והסרת תלמידים.
- לבבות עם ביטול, אזהרות בהקרנה והצעת תגובה הדורשת בחירה מפורשת.
- חלוקה אקראית של נוכחים, העברה ידנית בין קבוצות ופרסום מפורש להקרנה.
- שגרת כניסה, משימה נוכחית, כרטיס יציאה וסיכום אופציונלי.
- שמירה מקומית ושחזור לאחר רענון. איפוס דרך „על האבטיפוס”.

## גבולות האבטיפוס

ללא קוד חיבור פעיל הסנכרון מבוסס על localStorage ואירועי storage באותו דפדפן. חיבור עם קוד משתמש בשרת ובאחסון Redis משותף, כמפורט בהמשך. הכניסה נבדקת בצד הדפדפן ונשמרת ב־sessionStorage ללשונית. זו הדמיית כניסה בלבד, הניתנת לעקיפה; הסיסמה המשותפת אינה מפרידה באופן מאובטח בין מורים לאדמין. אין חשבונות אישיים או QR. מסלול הקוד כולל הרשאת מכשיר זמנית וסנכרון בין דפדפנים, אך הכניסה הראשונית עם 1111 היא כניסת הדגמה ולא אימות משתמשים אישי של מערכת ייצור. אין להזין פרטים אמיתיים של תלמידים. מפתח ההקרנה מקבל רק תוכן המיועד לתצוגה, אבל הפרדה זו אינה גבול אבטחה: כל הלשוניות באותו מקור יכולות לגשת לאחסון הדפדפן.

אפשר להציג את שקפי ההדגמה, להעלות PDF, תמונות, וידאו ואודיו או להוסיף קישור לאתר ול־YouTube. קבצים אחרים ניתנים לאחסון ולהורדה; הצגה ישירה של PowerPoint ושל מסמכי Office אינה נתמכת ויש לייצא אותם ל־PDF. שינוי סדר ושכפול שלבים ועריכת כרטיסים חופשית אינם כלולים עדיין. בכיתה ג׳2 נוכחות ברירת המחדל היא 22 מתוך 24 תלמידי הדגמה. כיתות אחרות מתחילות ברשימת תלמידים ריקה. הנתונים הקיימים מהאבטיפוס הקודם נשמרים תחת ג׳2. „שיחה אישית” היא הצעת הדגמה קבועה; הגדרת תגובות מותאמות תגיע בהמשך.

שינויים בקבוצות ובהנחיות הם טיוטה עד לפרסום מפורש. שעון השיעור מודד זמן מתחילת השיעור בנפרד מטיימר השלב. סיום הטיימר אינו מעביר שלב. התחלת שיעור מהתבנית מאפסת אזהרות ולבבות פעילים. נשמר סיכום כיתתי ללא שמות תלמידים כדי לצבור לבבות ולספור שיעורים שהסתיימו, בלי לספור סיום חוזר פעמיים. לבבות משיעור שהוחלף ללא סיום נשמרים גם הם בסיכום; הוא אינו נספר כשיעור שהסתיים. ביטול לב מתקן גם את הסכום המצטבר. לא נשמר ארכיון משמעת אישי. איפוס נתוני ההדגמה מאפס את הכיתה הנוכחית בלבד, כולל נתוניה המצטברים.

בהקרנה אמיתית יש לבחור תצוגה מורחבת במערכת ההפעלה, ולהעביר אליה רק את חלון ההקרנה.

## בדיקות

```sh
npm test
```

הבדיקות מכסות גם סיסמה שגויה, כניסה ויציאה בשני התפקידים, שחזור כניסה, הפרדת כיתות והקרנות, הוספת כיתה, צבירה בין שיעורים וסיום חוזר. בנוסף הן מכסות רצף שיעור, סנכרון הקרנה ושלט, הפרדת טיוטה מהקרנה, היעדרות וחלוקה לקבוצות, לב וביטול, שחזור טיימר, אזהרות בהקרנה, הוספת תלמידים והתאמה לרוחבי מסך שונים. בסביבת הענן נעשה שימוש ב־Chromium המותקן ב־`/usr/bin/chromium`. במחשב אחר אפשר להריץ `npx playwright install chromium`, או להגדיר `CHROMIUM_PATH` לנתיב דפדפן קיים.

## פתיחה ישירה במחשב, ללא התקנה

```sh
npm run export:html
```

הפקודה יוצרת את `downloads/beyachad.html`, המכיל את התוכנה, העיצוב וכל התלויות בקובץ אחד. מעתיקים את הקובץ למחשב ופותחים אותו ב־Chrome בלחיצה כפולה. הכניסה למורה ולאדמין היא עם `1111`. אין צורך להפעיל Node.js או שרת במחשב שבו פותחים את הקובץ.

קישורי ההקרנה והשלט נפתחים מאותו קובץ. הבדיקה אימתה ב־Chromium שהקובץ העצמאי עובד ללא בקשות לנכסים חיצוניים, כולל כניסה, הקרנה ואדמין. ניווט ישיר ל־`file:` חסום במדיניות דפדפן הבדיקה בענן, ולכן פתיחה ישירה כקובץ אינה מאומתת כאן. התנהגות אחסון של קבצי `file:` עשויה להשתנות בין דפדפנים. שמרו את הקובץ באותו מיקום כדי להמשיך לגשת לנתונים המקומיים. זו עדיין גרסת הדגמה בלבד.

הכתובת `localhost:5173` מתאימה רק כאשר שרת הפיתוח מופעל באותו מחשב שבו נפתח הדפדפן. הפעלת השרת בסביבת הענן אינה הופכת כתובת זו לנגישה ממחשב אחר.

## פריסה ב־Vercel

המאגר כולל `vercel.json` עם הגדרות Vite: התקנה באמצעות `npm ci`, בנייה באמצעות `npm run build` ופרסום תיקיית `dist`. רוב גרסת ההדגמה עובדת ללא משתני סביבה. לחיבור נייד באמצעות קוד נדרשים משתני Redis המתוארים בהמשך.

ב־Vercel בוחרים **Add New → Project**, מייבאים את `Sashka2022/class-management-`, מגדירים את שורש המאגר כתיקיית הפרויקט ולוחצים **Deploy**. לאחר חיבור GitHub, עדכונים לענף `main` יוכלו להתפרסם אוטומטית. נדרשת גישה לחשבון Vercel והרשאת גישה למאגר ב־GitHub.

הכתובת הציבורית תציג את אותה גרסת ההדגמה: הסיסמה המשותפת היא `1111`, הנתונים נשמרים מקומית בכל דפדפן והכניסה אינה מנגנון הרשאות שרת. אין להזין נתוני תלמידים אמיתיים.

## סטטוס תלמידים ותוכן מודולרי

במסך המורה במחשב ובהקרנה מוצג לוח סמלים של כל התלמידים לצד התוכן: נוכחות, לבבות ואזהרות (צהוב/אדום וגם סמל ומספר). האזהרות גלויות לכיתה לפי דרישת המוצר המעודכנת. המורה יכול לתת לב או אזהרה ישירות מהלוח; אירוע אחרי האזהרה השנייה ממשיך לדרוש בחירה בתגובה. לוח 24 תלמידי ההדגמה נבדק ללא צורך בגלילה ברוחב מחשב. בנייד, בטבלאות גדולות ובזום דפדפן מוגדל עשויה להידרש גלילה.

כפתור „תוכן, קבצים וקישורים” פותח ספרייה. העלאה שומרת טיוטה; רק „הצג לכיתה” מפרסם. „חלון נוסף” מציג אתר או YouTube לצד התוכן הנוכחי. קבצים עד 150MB נשמרים ב־IndexedDB בדפדפן ואינם מועלים לשרת; ההקרנה ניגשת אליהם באותו מקור ודפדפן. שמות ומזהי הקבצים נשמרים במצב הכיתה. האתר אינו עוקף חסימות iframe של אתרי צד שלישי. סרטונים מסוימים דורשים כניסה או אינם ניתנים להטמעה. הפעלה, עצירה, גלילה ומעבר עמודים בתוך התוכן המוטמע אינם מסונכרנים בין חלון המורה להקרנה; בוחרים את החלון שבו מפעילים את המדיה.

## רשימות, סדר יום, קבוצות ותבניות

ב„הכיתה שלי” בוחרים „הדבקת רשימת תלמידים”, מדביקים שמות (שם בכל שורה) או טוענים קובץ טקסט, בודקים את הכמות ומוסיפים את כולם יחד. תצוגת סמלי התלמידים ניתנת לצמצום ולהרחבה בנפרד במסך המורה ובהקרנה.

„המבט היומי” כולל סדר יום לפי תאריך (ברירת המחדל לפי שעון ישראל): שעה, פעילות והערה/ציוד. העריכה נשמרת אוטומטית לכיתה ולתאריך. ניתן לפרסם צילום מצב של סדר היום לכיתה בפעולה מפורשת.

„הקבוצות שלנו” מאפשר חלוקה אקראית לנוכחים או יצירת קבוצות ריקות ושיבוץ ידני. אפשר לשנות שם, להעביר תלמיד ללא קבוצה ולמחוק קבוצה בלי למחוק את תלמידיה. פרסום ההרכב נשאר פעולה מפורשת. ספריית התבניות מתחילה ריקה, ללא תבניות מוכנות מראש. המורה יוצר תבנית קבועה בטופס ריק: שם, שלבים, משך, הנחיה וציוד לפי בחירה. ניתן לערוך ולמחוק תבנית, לשמור אותה לכיתה ולהשתמש בה בשיעורים הבאים. אפשר גם לבחור במפורש לטעון את מהלך השיעור הפעיל לעריכה ולשמור אותו כתבנית. שינוי בשיעור שנוצר מתבנית אינו משנה את התבנית השמורה. תבניות אישיות קיימות נשמרות.

## חיבור נייד באמצעות קוד

1. במחשב פותחים „השלט שלי” ולוחצים „יצירת קוד חיבור”.
2. סורקים את ה־QR במצלמת הנייד. נפתח מסך החיבור באותו אתר עם הקוד מוכן; לוחצים „חיבור לשיעור”. לחלופין, בנייד פותחים את אותו אתר ובמסך הכניסה בוחרים „חיבור עם קוד ממחשב המורה”.
3. בהזנה ידנית מזינים את הקוד בן 8 הספרות. הקוד ניתן לשימוש פעם אחת ותוקפו עשר דקות; חיבור השיעור תקף עד ארבע שעות.
4. מכשיר המחשב יכול לנתק את החיבור. אין להעביר קוד למי שאינו אמור לצפות ולשלוט בכיתה.

הפעולות מסתנכרנות דרך API עם השוואת גרסאות, כתיבה אטומית ומזהה פעולה למניעת ביצוע חוזר. המצב נבדק בערך כל 1.5 שניות. הסודות של המכשירים נשמרים ב־sessionStorage בלשונית; בשרת נשמרות גיבובות שלהם. לשיעור יש תוקף מוגבל ואין שמירה בענן ללא הגבלה. שגיאת שרת מוצגת ולא מתבצע שינוי מקומי שיתחזה לסנכרון.

בפיתוח (`npm run dev`) שרת Vite מספק אחסון זמני בזיכרון, שמתאפס בעת עצירת השרת. בדיקת הדפדפן מכסה שני הקשרי דפדפן נפרדים ללא אחסון משותף. לגישה מטלפון נדרשת כתובת האתר הנגישה לטלפון; כתובת localhost של מחשב אחר לא תעבוד. בקובץ ה־HTML העצמאי אין שרת ולכן חיבור הקוד אינו נתמך.

### הגדרה ב־Vercel — נדרשת לפני חיבור מכשירים באתר

מחברים מסד Upstash Redis לפרויקט באמצעות Marketplace של Vercel. מגדירים בפרויקט את `KV_REST_API_URL` ואת `KV_REST_API_TOKEN` (או את זוג השמות `UPSTASH_REDIS_REST_URL` ו־`UPSTASH_REDIS_REST_TOKEN`), עבור סביבות הפריסה הרצויות, ומבצעים Redeploy. הערכים מוזנים בהגדרות המאובטחות של Vercel בלבד, ולא בקוד או בצ׳אט. `.env.example` מציג שמות בלבד.

ללא אחסון מוגדר, `/api/pair` מחזיר הודעת 503 ברורה ולא מייצר קוד מדומה. בסביבת העבודה הנוכחית אין הגדרות Redis, ולכן הפריסה ב־Vercel וחיבור למסד אמיתי טרם אומתו. מנגנון הכתיבה האטומית ב־Redis משתמש ב־Lua CAS; נבדקו מקומית הרשאות, שימוש יחיד בקוד, התנגשות גרסאות, מניעת כפילויות וניתוק.

קבצים שהועלו ל־IndexedDB אינם מועברים לנייד; הוא עדיין יכול לשלוט בתוכן שבמחשב, אך לא יציג תצוגה מקדימה של קובץ שלא נמצא אצלו. אתרים וקישורי מדיה נגישים בשני המכשירים; ניגון בתוך iframe אינו מסונכרן. דוח האדמין נשאר סיכום הכיתות שנשמרו בדפדפן שלו ואינו מסד נתונים בית־ספרי מרכזי.

## מצב כיתה ושווה ציטוט

במסך השיעור ובשלט הנייד נוספו „מצב כיתה” ו„שווה ציטוט”. בחירת מצב מציגה מיד אייקון וכותרת בולטים לצד המצגת או התוכן הנוכחי, גם בהקרנה. המצבים המוכנים הם הקשבה, עבודה שקטה, עבודה בזוגות, קבוצות, שיחה ותנועה. אפשר להגדיר גם אייקון וכותרת אישיים ולהסיר את התצוגה. בחירת מצב אינה מחליפה שקף, פעילות או חלון מדיה נוסף. המצב נשמר ברענון ומתאפס בתחילת שיעור חדש.

„שווה ציטוט” פותח מחברת נפרדת לכיתה: מזינים אמירה, משייכים תלמיד/ה לפי בחירה ושומרים. כל ציטוט כולל תאריך ושעת שמירה לפי שעון ישראל. אפשר לערוך, למחוק ולסנן לשיעור הנוכחי; הציטוטים נשמרים גם במעבר לשיעור חדש. המחברת אינה נשלחת לתצוגת ההקרנה. רק בחירה מפורשת ב„הצגת הציטוט לכיתה” מפרסמת צילום מצב של הטקסט והשם שנבחרו. עריכת ציטוט שמור אינה משנה את הטקסט המוקרן עד לפרסום חוזר; מחיקת ציטוט שמוצג כרגע מחזירה למצגת. חזרה למצגת שומרת את מיקום השקף הקודם.

בדיקות הדפדפן מכסות בחירה והסרה של מצב כיתה לצד המצגת, מצב אישי, שחזור אחרי רענון, איפוס בתחילת שיעור, שמירת ציטוט פרטי, פרסום מפורש, עריכה ללא שינוי ההקרנה, שמירה בין שיעורים, סינון ומחיקה. במסלול החיבור עם קוד המחברת משותפת לשני מכשירי המורה יחד עם מצב השיעור; הפעלת מסלול זה ב־Vercel עדיין דורשת את הגדרת Redis המתוארת לעיל.

### הפעלת שליטת נייד ב־Vercel — סדר הפעולות

1. פותחים את הפרויקט ב־Vercel ובוחרים Storage או Marketplace, בהתאם לתצוגת החשבון.
2. מוסיפים Upstash Redis ומחברים אותו לאותו פרויקט.
3. ב־Settings → Environment Variables מוודאים שמוגדרים זוג משתני REST הנתמכים בקוד, ושמורשים לסביבת Production (וגם Preview אם רוצים לבדוק פריסות תצוגה). כתובת המסד היא כתובת REST ב־HTTPS, והטוקן צריך לאפשר כתיבה. את הערכים מעתיקים רק מהגדרות המסד להגדרות Vercel.
4. ב־Deployments בוחרים את הפריסה העדכנית ומבצעים Redeploy כדי שהמשתנים ייטענו.
5. פותחים את כתובת ה־HTTPS הציבורית של האתר במחשב ובנייד. במחשב: „השלט שלי” → „יצירת קוד חיבור”. בנייד: „חיבור עם קוד ממחשב המורה” → הזנת שמונה הספרות.

אין צורך להתקין תוכנה בנייד. אין להחליף את כתובת האתר ב־localhost. אם ההגדרה חסרה או שהמסד אינו זמין, מוצגת הודעת שגיאה במקום קוד חיבור. פריסה והגדרה בפועל בחשבון Vercel דורשות גישה לחשבון ואינן ניתנות לאימות מהסביבה הנוכחית.

## חיבור באמצעות QR

בחלון „השלט שלי” נוצר QR יחד עם קוד החיבור. יצירת התמונה מתבצעת בדפדפן, ללא שירות QR חיצוני או תשלום נוסף על יצירת QR. הסריקה פותחת את האתר באותו מקור ובנתיב של מסך החיבור; הקוד מועבר בחלק ה־fragment (`#code=…`) כדי שלא להופיע בכתובת בקשת HTTP לשרת. הקוד נמחק מהכתובת אחרי מילוי הטופס. נדרשת לחיצה מפורשת על „חיבור לשיעור”; פתיחת הקישור לבדה אינה צורכת אותו. סודות מכשיר, טוקן המחשב וסיסמת הכניסה אינם כלולים ב־QR.

התמונה מוסתרת אחרי חיבור המכשיר, אחרי עשר דקות או בניתוק. נשארת אפשרות להזנה ידנית כל עוד הקוד תקף. הסריקה מטלפון דורשת כתובת אתר ציבורית או כתובת רשת שנגישה לטלפון; localhost של המחשב אינו נגיש אוטומטית מהנייד. אין להקרין QR או קוד חיבור לתלמידים. הגדרת Redis ב־Vercel עדיין נדרשת.

בדיקות הדפדפן מפענחות את הפיקסלים בפועל של ה־QR, פותחות את הקישור בדפדפן נפרד, מאמתות מילוי אוטומטי ושליטה בשיעור, ובודקות הסתרה לאחר שימוש ופקיעת תוקף.

כותרת מצב הכיתה נשברת רק בין מילים, ללא פיצול מילה באמצע. גודל הגופן מותאם אוטומטית לרוחב ולגובה המסגרת בעת בחירת מצב ושינוי גודל החלון. הבדיקה מודדת את גבולות כל מילה ברוחבי מחשב, טאבלט ונייד, וגם עם חלון מדיה נוסף וכותרת אישית ארוכה.

## תפקידים בקבוצות

חלון הקבוצות כולל הסבר על ארבעה תפקידים: מוביל/ת קבוצה (הבנת המשימה ושיתוף כולם), מתעד/ת (כתיבה וציור), אחראי/ת זמן (מעקב אחרי הזמן) ומציג/ה (שיתוף תוצרי הקבוצה). ליד כל תלמיד משובץ יש בחירת תפקיד ואייקון, עם שלושה אייקונים מתאימים לכל תפקיד. ניתן להקצות אותו תפקיד לכמה תלמידים באותה קבוצה, ואין חובה להקצות את כל התפקידים. בחירת „ללא תפקיד” מסירה את השיוך; האייקון האישי הקבוע של התלמיד אינו משתנה.

השיוכים נשמרים לכיתה ולשיעור ברענון, במעבר בין קבוצות ובחלוקה אקראית מחודשת, ומתאפסים בתחילת שיעור חדש. שינוי תפקיד או אייקון נשמר בטיוטה; „הצג קבוצות לכיתה” מפרסם צילום מצב הכולל את התפקידים והאייקונים לצד השמות. שינוי נוסף אינו משנה את ההקרנה עד לפרסום חוזר. השיוכים מסתנכרנים גם בין מכשירי המורה דרך חיבור הקוד הקיים, כאשר שירות הסנכרון מוגדר.
